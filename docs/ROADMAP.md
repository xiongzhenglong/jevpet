# 路线图

路线图以可运行的纵向体验为单位，不按技术层无限横向铺开。

## M0：项目基线

- [x] 创建独立仓库。
- [x] 写明产品范围与架构边界。
- [x] 建立跨设备交接流程。
- [x] 添加基础检查脚本和秘密文件规则。
- [ ] 初始化 Flutter 应用。
- [ ] 记录并固定 Flutter/Dart 版本。

完成标准：新电脑克隆仓库后能根据文档进入开发状态。

## M1：单次互动垂直切片

- [ ] 创建房间场景和临时宠物占位图。
- [ ] 实现 `PetState`、`UserEvent`、`PetAction`。
- [ ] 点击宠物时立即抬头/跳跃。
- [ ] 本地 Planner 生成一份行为计划。
- [ ] Executor 顺序执行动作。
- [ ] SQLite 保存并恢复状态。
- [ ] 增加基础单元测试和调试事件面板。

完成标准：关闭再打开应用后，宠物状态仍保留；一次点击能完整经历事件、计划、执行和存档。

## M2：Jev 成为规划器

- [ ] 定义 Action Registry 与版本化 schema。
- [ ] 建立最小服务端代理，密钥不进入客户端。
- [ ] 接入 Jev Planner。
- [ ] 实现超时、校验失败和无网络 fallback。
- [ ] 保存 Jev 输入摘要、计划和执行结果。
- [ ] 制作可回放的 20 个行为场景测试集。

完成标准：Jev 能在至少 10 个能力之间选择和组合；失败时用户仍能流畅互动。

## M3：动态房间 UI

- [ ] 建立 Dynamic UI Registry。
- [ ] 定义 `UiPatch` DSL 与 schema。
- [ ] 实现状态卡、选择卡、记忆便签、物品卡。
- [ ] 缓存相同上下文的 UI 组合。
- [ ] 加入布局预算、组件白名单和自动消失策略。

完成标准：同一房间可以按状态组合出不同辅助界面，但视觉仍统一且无需生成客户端代码。

## M4：陪伴与个性

- [ ] 引入短期事件记忆和长期关系摘要。
- [ ] 增加昼夜节律与自主行为。
- [ ] 接入低成本对话润色模型。
- [ ] 加入人格参数，但不允许越过动作能力边界。
- [ ] 评估声音、通知和桌面驻留体验。

## M5：移动端打包

- [ ] Android 真机性能和电量测试。
- [ ] 图标、启动页、签名与隐私说明。
- [ ] 离线/弱网/升级迁移测试。
- [ ] 生成 Android APK/AAB。
- [ ] 在具备 macOS/Xcode 环境后评估 iOS。

## 暂存想法

- 房间主题与季节变化。
- 用户制作但受 schema 限制的物品包。
- 宠物行为时间线与“为什么这样做”的调试视图。
- 多宠物之间的关系与能力组合。
