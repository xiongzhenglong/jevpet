# 产品说明

## 一句话定义

JevPet 是一个拥有连续状态、会在房间中自主生活、能够把用户意图组合成可见行为的虚拟互动宠物。

它不是聊天机器人加一张立绘。对话只是输入方式之一；走动、观察、休息、玩耍、回应环境和形成习惯才是主体。

## 用户体验目标

用户每天打开应用几十秒，也能感到宠物“记得我、正在生活、会因为我做了什么而改变”。

体验关键词：

- 温暖而克制：不过度打扰，不制造强迫签到。
- 即时而有生命感：触摸后 100ms 级出现本地反馈。
- 可解释但不机械：动作由状态和能力组合产生，可以调试和回放。
- 有惊喜但不失控：Jev 提供组合变化，应用掌握允许发生的事情。
- 离线可玩：没有模型也能完成主要互动循环。

## 核心循环

1. 用户进入房间，观察宠物此刻在做什么。
2. 用户点击、呼唤、喂食、放置物品或输入一句话。
3. 宠物立即用视线、音效或短动画确认收到互动。
4. 系统结合宠物状态、房间状态和历史选择一个行为计划。
5. 执行一组连续动作，并更新宠物状态与关系记忆。
6. 结果被保存，下次进入时继续，而不是重新开始。

## MVP 范围

第一版只证明一个闭环：

- 一个房间场景。
- 一个临时宠物形象。
- `idle`、`look`、`walk`、`happy`、`sleep` 五类视觉状态。
- 点击、呼唤、喂食、玩耍四种用户行为。
- 情绪、精力、饱腹、亲密度四个状态值。
- 本地规则可以独立生成行为计划。
- Jev 可以在可用时替换或增强规划步骤。
- SQLite 保存状态和最近事件。
- 一个仅开发环境可见的事件/计划调试面板。

## MVP 明确不做

- 开放世界、多房间地图和复杂寻路。
- 用户上传任意脚本或模型生成任意代码。
- 宠物交易、付费抽卡、排行榜和社交系统。
- 语音克隆、长期开放麦克风和后台持续监听。
- 大量宠物、美术皮肤或完整装扮商城。
- 在每次点击时调用大模型。

## 智能分层

### 第一层：即时反射

完全本地执行，例如看向触点、耳朵抖动、发出短音效。目标是立即反馈。

### 第二层：本地行为

状态机和规则系统完成大部分日常活动，例如困了走向床、饥饿时看向饭盆。

### 第三层：Jev 组合规划

当输入含糊、能力较多或需要多步组合时，Jev 从能力注册表中选择动作，输出受限计划。

### 第四层：廉价对话模型

只负责把已经确定的意图和情绪写成自然语言，不决定能否执行动作，也不修改核心状态。

## 动态 UI

动态 UI 不等于每次让模型生成完整页面。应用维护一个受控组件目录：状态卡、物品卡、选择条、对话气泡、任务便签、关系回忆等。Planner 只能返回组件 ID、数据和布局提示。

这样可以同时获得动态组合、稳定视觉、毫秒级渲染和可缓存结果。

## 质量与性能目标

- 触摸后的视觉确认：目标小于 100ms。
- 本地行为计划：目标小于 50ms。
- Jev 决策：允许 1–3 秒，但期间必须继续本地动作。
- 无网或超时：自动回退，不弹出阻塞式错误。
- 同一事件日志可以重放出相同的状态变化。
- 首个垂直切片以流畅和完整为优先，不追求美术数量。

## 成功标准

当一个不了解实现的人连续互动三分钟，能够说出宠物此刻的心情、正在做什么，以及它为什么这样回应，就证明方向基本成立。
